# 运行帧刚开始时叫 Agent：原因是背包事实，不是选项太少（Claude，2026-10-15）

用户：「第二个你自己研究。」问题：只有「继续 / 叫 Agent」两个选项的运行帧，调用刚开始时偶尔叫 Agent（备用装备和第 5 步两次运行共 5 次，概率 0.54–0.61）。

## 先看数据（6 次真实运行，`bench/twoopt-survey.py`、`twoopt-early.py`）

| 运行帧选项 | 帧数 | 叫 Agent |
|---|---|---|
| 继续 / 叫 Agent | 892 | 5（**全部在调用开始后 3 秒内**；早期 216 帧占 2.3%，之后 676 帧 0 次） |
| 继续 / 中断 / 叫 Agent | 76 | 0 |

问题不在「两个选项」，在调用刚开始那几帧。早期帧里，进度行写的是「no real progress has been observed yet.」，怀疑这句读起来像「卡住了」。

## 离线试验：只改这一句（`bench/progress-line-trial.py`）

带这句的两选项帧共 137 个（早期 132），用记录里的原请求重放，每帧两种选项顺序。基线复现线上答案 136/137。

| 写法 | 早期帧叫 Agent（264 问） | 后期帧（10 问） |
|---|---|---|
| V0 原句 | 7 | 0 |
| V1「no progress event since the call started.」 | 10 | 1 |
| V2 同上加「…{elapsed}s ago」 | 7 | 0 |
| V3 不出这一行 | 6 | 0 |

改这句没有用，而且叫 Agent 总落在同几帧上。

## 逐帧看那几帧

- threat7 seq1885、threat8 seq1810：`craft_item(oak_planks, 12)` 开始 1 秒，题面背包是「oak_log 0 或 1、oak_planks 4」，按题面材料确实不够做 12 块。但 claude8 那次线上继续做下去，合成成功，合成前是 oak_log 4、没有木板，结束时 oak_log 1、oak_planks 12（用掉 3 根）。合成进行中题面是 oak_log 1、oak_planks 4，另外两根原木在合成格里，身体却报「背包完整」并且没算它们。Decision 照着少了原料的背包叫 Agent，错的是事实。
- spare3 seq7985（第一次 `dig_up`）：意图写着「cobblestone 3 还留在背包里」，`dig_up` 正要拿圆石垫脚，两者冲突，叫 Agent 有道理。
- spare3 seq10347、10541（后两次 `dig_up`）：找不出原因，892 帧里 2 帧，当作模型噪声。

## 修法（身体端，Java）

真人玩家看得见合成格里的东西。读背包时，把打开的合成格（2×2 和工作台 3×3）里的物品和鼠标上拿着的物品也算进去；`inventory_count_scope` 相应改名。没有改题目文字，没有加阈值或场景判断。

验证：Java 编译和客户端单元测试通过（`2f7ab91`）。真实运行 `step5-threat-claude11` 里客户端确实是新代码（事实里的统计范围是新名字，共 1063 处），合成途中各帧的背包和合成前后对得上（例：6 原木 → 中途 5 原木 + 4 木板 → 12 木板）。但没有碰巧抓到「原料正好在合成格里」的那一帧，所以只能说没再看到少算，正面证据不够硬。
